# S3 general purpose bucket

## Purpose

Object storage: files, backups, static assets, logs, build artefacts. Use it when data is written and read as whole
objects. Not for databases, file systems that need POSIX semantics, or data that needs transactions.

## Behaviour

- **Global name.** A bucket name is unique across all accounts and Regions of the partition, and cannot be
  changed, nor can its Region (S8, S12). After a bucket is deleted another account can take the name and receive
  requests meant for the old bucket, so AWS advises emptying and keeping a bucket instead of deleting it to free
  the name (S8). The account regional namespace (`<prefix>-<account>-<region>-an`) guarantees only your account can
  own the name (S8).
- **Private by default.** New buckets and objects do not allow public access; Block Public Access overrides
  policies and ACLs that would grant it (S9). Terraform's `aws_s3_bucket_public_access_block` defaults all four
  flags to false (S2), so the platform sets them explicitly.
- **Block Public Access settings** (S9): `block_public_acls` rejects public ACLs on new requests;
  `ignore_public_acls` ignores existing public ACLs; `block_public_policy` rejects a bucket policy that grants
  public access; `restrict_public_buckets` limits a bucket with a public policy to the owner account and AWS
  service principals. They do not change stored policies or ACLs, so removing a setting makes an old public policy
  effective again. They can be set per bucket, per access point, per account or per Organization, and the most
  restrictive combination applies (S9).
- **What counts as a public policy.** S3 assumes a policy is public until it is shown not to be, which needs fixed
  (non-wildcard) values for a principal or for one of the condition keys `aws:SourceArn`, `aws:SourceVpc`,
  `aws:SourceVpce`, `aws:SourceAccount`, `aws:SourceOwner`, `aws:PrincipalOrgID`, `aws:SourceIp`, and similar (S9).
  A statement with `"Principal": "*"` and no such fixed condition makes the whole policy public (S9).
- **Object Ownership.** New buckets default to Bucket owner enforced, which disables ACLs; access is then managed
  only by policies (S11, S13). CloudFront OAC requires Bucket owner enforced or Bucket owner preferred (S11 and
  [resource-policy](../relations/resource-policy.md)).
- **Encryption.** Every bucket encrypts new objects with SSE-S3 by default at no cost (S10). SSE-KMS and DSSE-KMS
  are options; they are subject to KMS request rate quotas (S10). Objects stored before a change keep their old
  encryption (S10). Destroying the encryption resource resets the bucket to the default (S4). SSE-C is blocked by
  default on new buckets from spring 2026; the provider pages give two different months (S1, S4).
- **Versioning.** Cannot return to unversioned once enabled, only be suspended; AWS recommends waiting about 15
  minutes after enabling (S5). Object Lock turns versioning on permanently (S1).
- **Lifecycle.** One configuration per bucket. A bucket policy cannot stop a lifecycle rule from running (S13).
- **Bucket policy.** A resource-based policy, set only by the bucket owner, at most 20 KB. It applies to objects
  owned by the bucket owner (S13). There can be only one per bucket (S3), so everything that needs a statement
  (CloudFront, load balancer logs, anything else) must be merged into that one document
  ([resource-policy](../relations/resource-policy.md)).
- **Reaching S3 from a VPC.** S3 has a public endpoint. A workload in a private subnet reaches it through a NAT
  gateway or a VPC gateway endpoint ([vpc-endpoint-s3](vpc-endpoint-s3.md), Tier 1 since decision D-029). See
  [egress-path](../relations/egress-path.md) and rule [VAL-070](../rules/validation.md).

## Placement

Regional, outside any VPC.

## Relations

- [resource-policy](../relations/resource-policy.md): bucket policy statements for CloudFront OAC and
  load-balancer access logs.
- [grant](../relations/grant.md): IAM roles allowed to read or write. In one account a grant alone is enough; no bucket
  policy is needed.
- origin: CloudFront origin; written with CloudFront.
- [egress-path](../relations/egress-path.md): the network path a workload uses to reach S3.

## Failure modes

| Situation | Result |
|---|---|
| Name not available | Create fails; names are global (S8). Rule [VAL-050](../rules/validation.md) covers format only |
| Name contains a period | Virtual-hosted HTTPS requests fail certificate validation (S8) |
| Bucket policy with a public statement while `block_public_policy` is on | `PutBucketPolicy` is rejected (S2, S9). Rule [VAL-052](../rules/validation.md) |
| Two `aws_s3_bucket_policy` resources for one bucket | The last one silently wins (S3). Rule [VAL-051](../rules/validation.md) |
| Policy larger than 20 KB | Rejected (S3). Rule [VAL-053](../rules/validation.md) |
| Non-current-version lifecycle rule without versioning | Rejected or has no effect (S7). Rule [VAL-056](../rules/validation.md) |
| Versioning set back to `Disabled` | Provider error; the API cannot return a bucket to unversioned (S5). Pitfall P-038 |
| Object Lock enabled, then versioning suspended | Not allowed (S1). Rule [VAL-057](../rules/validation.md) |
| Destroy a bucket that holds objects | Fails unless `force_destroy` was applied first (S1). Pitfall P-035 |
| Several lifecycle resources on one bucket | Permanent diff (S7). Pitfall P-037 |
| Access-log or ALB log bucket uses SSE-KMS default encryption | Delivery may write objects you cannot read; the destination must use SSE-S3 (S10 and [resource-policy](../relations/resource-policy.md)) |

## Limits, cost, security

See front matter. Security: turn on all four Block Public Access flags ([SEC-012](../rules/security.md)), keep ACLs
off ([SEC-014](../rules/security.md)), consider versioning ([SEC-013](../rules/security.md)).

## Terraform mapping

`aws_s3_bucket` (`bucket`, `force_destroy`, `object_lock_enabled`, `tags`) plus one separate resource per
setting: `aws_s3_bucket_public_access_block`, `aws_s3_bucket_ownership_controls`, `aws_s3_bucket_versioning`,
`aws_s3_bucket_server_side_encryption_configuration`, `aws_s3_bucket_lifecycle_configuration` and, at most one,
`aws_s3_bucket_policy`. The inline arguments of `aws_s3_bucket` (`acl`, `versioning`, `lifecycle_rule`, `policy`,
`server_side_encryption_configuration`, `logging`, `cors_rule`, `website` and others) are deprecated, are not
tracked for changes after creation, and must not be mixed with the separate resources (S1). Order: the bucket,
then the public access block, then the bucket policy, with `depends_on` the access block so a public-policy check
is not racing it (the pages read do not state the race; unverified).
