# Terraform pitfalls

Behaviours of the AWS provider and Terraform/OpenTofu that the platform must design around. This file covers
networking (P-001 to P-017), compute and containers (P-018 to P-034) and storage and databases (P-035 to P-044) and delivery and certificates (P-045 to P-059) and IAM (P-060 to P-069) and the S3 gateway endpoint (P-070 to P-074). Each entry says what happens, why it matters, and what the generator must do.

Sources: provider documentation under
https://raw.githubusercontent.com/hashicorp/terraform-provider-aws/main/website/docs/r/ for `vpc`, `subnet`,
`internet_gateway`, `nat_gateway`, `route_table`, `route`, `route_table_association`, `security_group`,
`vpc_security_group_ingress_rule`, `eip` (`.html.markdown`).

| # | Pitfall | What happens | Generator must | Status |
|---|---|---|---|---|
| P-001 | Inline `route` blocks and `aws_route` together | Rules conflict and overwrite each other. An empty inline list deletes all managed routes | Emit `aws_route` only, never inline blocks | verified |
| P-002 | Inline `ingress`/`egress` and rule resources together | Perpetual diffs, overwritten rules. Removing inline blocks does not remove rules | Emit no inline rules; use `aws_vpc_security_group_*_rule` one per rule | verified |
| P-003 | Default egress rule | AWS adds allow-all egress to a new group; Terraform removes it at creation | Always emit egress rules explicitly, including a deliberate allow-all rule when wanted | verified |
| P-004 | `gateway_id` given a NAT gateway ID | AWS accepts it, then returns a more specific attribute; permanent diff | Use `nat_gateway_id` for NAT targets, `gateway_id` only for internet gateways | verified |
| P-005 | Security group `name`, `description`, `vpc_id` are ForceNew | Changing any replaces the group; the old one cannot be deleted while attached ("Security Group Deletion Problem") | Warn before changing them. Use `create_before_destroy` with `name_prefix`, or `replace_triggered_by`. The provider discourages provisioners | verified |
| P-006 | Security group description cannot be empty and has no update API | Empty value rejected; edits force replacement | Default a non-empty description; treat description as immutable in the UI | verified |
| P-007 | Elastic IP and NAT gateway need the internet gateway first | Creation can fail on ordering | Add `depends_on = [aws_internet_gateway.<x>]` to EIPs, public NAT gateways and instances that use public addresses | verified |
| P-008 | Elastic IP attached to a NAT gateway through `network_interface` | `AuthFailure` | Pass `allocation_id` to the NAT gateway | verified |
| P-009 | `aws_internet_gateway.vpc_id` and `aws_internet_gateway_attachment` | Two ways to attach; mixing them conflicts | Use `vpc_id` on the gateway; never emit the attachment resource | verified (the conflict itself is inferred; the page offers them as alternatives) |
| P-010 | Subnet deletion with Lambda interfaces | Delete can take up to 45 minutes | Allow a long delete timeout; destroy functions first | verified |
| P-011 | Route table association on a subnet that already has one | `Resource.AlreadyAssociated` | Emit one association per subnet; for existing infrastructure import first | verified |
| P-012 | Main route table is implicit | Subnets without an explicit association follow it silently | Emit an explicit association for every subnet | verified |
| P-013 | `aws_vpc` creates a default route table, security group and network ACL | They exist outside the design and the security group is open | Decide whether to manage them with `aws_default_security_group` etc. (decision D-006) | verified (existence); `aws_default_*` resources unverified |
| P-014 | Regional NAT gateway `availability_zone_address` blocks | Adding or removing them recreates the gateway; moving an allocation between AZs needs two applies | Treat the AZ list as immutable once created | verified |
| P-015 | `secondary_allocation_ids` with `aws_nat_gateway_eip_association` | Perpetual diff and overwritten associations | Use one or the other | verified |
| P-016 | Duplicate security group rules | AWS rejects the second identical rule | Deduplicate rules by content before emitting | unverified |
| P-017 | Destroy order | A security group referenced by another group's rule, a gateway with public addresses in use, and a subnet with interfaces all block deletion | Rely on attribute references for ordering; keep rules as separate resources so mutual references do not form a cycle | verified (individual cases); cycle claim inferred |
| P-018 | EC2 `user_data` change | Stops and starts the instance by default; replaces it only with `user_data_replace_on_change = true` | Expose the choice; default to the safer behaviour per workload | verified |
| P-019 | EC2 `security_groups` in a VPC | The argument is for EC2-Classic and the default VPC | Emit `vpc_security_group_ids` | verified |
| P-020 | EC2 `network_interface` and `ebs_block_device` | `network_interface` is deprecated and its change recreates the instance. `ebs_block_device` mixed with `aws_ebs_volume` or `aws_volume_attachment` conflicts | Use `primary_network_interface`; keep extra volumes in one style | verified |
| P-021 | EC2 public IP after Elastic IP attach | `public_ip` changes after attachment | Reference the Elastic IP address, not the instance attribute | verified |
| P-022 | EC2 root volume encryption | Changing `encrypted` or `kms_key_id` replaces the instance | Set encryption at creation; warn before changing | verified |
| P-023 | Lambda VPC interface cleanup | Removing the VPC config takes up to 20 minutes to delete the interface; deleting the execution role first strands the interface; subnet and security group deletion can wait up to 45 minutes | Destroy functions before roles, subnets and groups; allow long delete timeouts | verified |
| P-024 | Lambda role recreated | Existing function can fail with `KMSAccessDeniedException` | Do not replace the role of an existing function in place; switch away and back or recreate the function | verified |
| P-025 | Lambda log group ordering | Function can create its own log group before Terraform does | Create `aws_cloudwatch_log_group` first and `depends_on` it | verified |
| P-026 | Lambda code change detection | `source_code_hash` sees local changes only; `code_sha256` sees out-of-band changes too, and for images comes from the digest | Emit `source_code_hash` for zip from a local file, `code_sha256` for images | verified |
| P-027 | Lambda package type | Cannot change Zip to Image on an existing function | Treat as replace | verified |
| P-028 | ECS service delete race | Role policy destroyed first leaves the service stuck in `DRAINING` | `depends_on` the role policy | verified |
| P-029 | ECS desired count and autoscaling | Terraform resets the count | `lifecycle { ignore_changes = [desired_count] }` when something else manages it | verified |
| P-030 | ECS task definition changes | Every change to `container_definitions` is a new revision; formatting or escaping differences appear as diffs | Generate the JSON with `jsonencode`, in a stable key order | verified |
| P-031 | ECS service defaults | `desired_count` 0, `launch_type` EC2, `assign_public_ip` false, `security_groups` the VPC default group | Always emit all four explicitly | verified |
| P-032 | ECS capacity provider strategy change | Needs `force_new_deployment = true` | Emit it when the strategy changes | verified |
| P-033 | ECR lifecycle policy order and repository delete | Unsorted `rulePriority` causes a change on every plan; a repository with images is not deleted unless `force_delete = true` | Sort rules; decide `force_delete` explicitly | verified |
| P-034 | ECS service-linked role | Needed by ECS; created with a cluster or from the console | Check whether Terraform must create it (`aws_iam_service_linked_role`); the pages read do not say | unverified |
| P-035 | S3 bucket destroy | `force_destroy` deletes all objects, including locked ones, and only takes effect after an apply that sets it; not effective in the same operation that replaces or destroys the bucket | Apply `force_destroy` before a destroy that must empty the bucket; default false | verified |
| P-036 | S3 inline arguments | `acl`, `versioning`, `lifecycle_rule`, `policy`, `server_side_encryption_configuration`, `logging`, `cors_rule`, `website` and others on `aws_s3_bucket` are deprecated and not tracked for later changes; mixing them with the separate resources conflicts | Emit only the separate resources | verified |
| P-037 | S3 lifecycle configuration | One per bucket; several resources give a permanent diff; changes take time to propagate; a rule on noncurrent versions needs `depends_on` the versioning resource | One lifecycle resource per bucket, with `depends_on` versioning | verified |
| P-038 | S3 versioning | Cannot go back to unversioned; `Disabled` after `Enabled` errors; about 15 minutes should pass before writing objects; Object Lock turns versioning on permanently | Never emit `Disabled` on an existing bucket; delay object creation in the same configuration | verified |
| P-039 | RDS password in state | `password` and all other arguments are stored in plain text in state | Prefer `manage_master_user_password`; or `password_wo` with `password_wo_version` on Terraform 1.11 or later | verified |
| P-040 | RDS encryption | `storage_encrypted` and `kms_key_id` cannot change in place | Decide encryption before creation; changing means replace through an encrypted snapshot copy or blue/green | verified |
| P-041 | RDS pending changes | Storage and other changes can wait for the maintenance window so Terraform shows a diff meanwhile; `apply_immediately` applies now and may reboot; storage autoscaling hides `allocated_storage` drift | Expose `apply_immediately` explicitly; set `max_allocated_storage` only when autoscaling is wanted | verified |
| P-042 | RDS delete and managed secret | A final snapshot needs `final_snapshot_identifier` unless skipped; `deletion_protection` blocks delete; the managed secret rotates every 7 days and is deleted with the instance; stopping rotation needs `aws_secretsmanager_secret_rotation` referencing `master_user_secret[0].secret_arn` | Set both explicitly; order secret resources after the instance | verified |
| P-043 | S3 bucket policy | Only one `aws_s3_bucket_policy` per bucket; `PutBucketPolicy` replaces everything silently | Merge all statements into one resource; derive Sids from relation IDs | verified |
| P-044 | S3 policy and public access block ordering | A public-policy check could race the access block; the provider pages do not state it | `depends_on` the public access block from the policy | unverified |
| P-045 | ALB listener | Changing `load_balancer_arn` replaces the listener | Treat the listener as tied to its load balancer | verified |
| P-046 | ALB target group | `name`, `name_prefix`, `port`, `protocol`, `protocol_version`, `target_type`, `vpc_id` and `ip_address_type` force a new target group; an ALB listener or ECS service that references it must be updated or replaced first | Warn before changing them. A zero-downtime replacement pattern (`create_before_destroy` with `name_prefix`) is not described on the provider page and is `unverified` | verified (ForceNew list); mitigation unverified |
| P-047 | ALB Lambda target | The attachment needs an `aws_lambda_permission` for `elasticloadbalancing.amazonaws.com` and `depends_on` it | Emit both; order the attachment after the permission | verified |
| P-048 | ACM certificate replacement | A certificate that a listener or distribution uses cannot be swapped without a gap | `lifecycle { create_before_destroy = true }` on the certificate | verified |
| P-049 | ACM validation records | `domain_validation_options` repeats the record for an apex and its wildcard; the validation resource waits up to 75 minutes and does not create DNS records | Key records by record name, `allow_overwrite = true`, pass `validation_record_fqdns` | verified |
| P-050 | CloudFront deployment | A create or update takes about 15 minutes to reach `Deployed`, deletes of related resources are blocked meanwhile; destroying an enabled distribution is slow | Allow long timeouts; `retain_on_delete` only deliberately | verified |
| P-051 | CloudFront viewer certificate Region | The ACM certificate must be in `us-east-1` | Create it through a provider alias for `us-east-1` | verified |
| P-052 | CloudFront and S3 policy ordering | Use `origin_access_control_id` or `s3_origin_config`, not both for one need. The bucket policy references the distribution ARN while the distribution references the bucket, so the policy must be its own resource created after both | Emit the bucket policy as a separate merged resource after the distribution | verified (exclusivity); ordering inferred |
| P-053 | Route 53 alias | `ttl` and `records` conflict with `alias`; the TTL of an alias is fixed at 60 seconds | Never emit `ttl` on an alias | verified |
| P-054 | Route 53 zones | Inline `vpc` blocks and `aws_route53_zone_association` conflict (private zones); a subdomain zone needs an NS record in the parent; `force_destroy` removes all records | Public zones only for now; add the parent NS record; default `force_destroy` false | verified |
| P-055 | Route 53 TXT | Values over 255 characters need embedded quoting | Split long TXT values | verified |
| P-056 | Route 53 NS and SOA | Created with the zone; managing them needs import or `allow_overwrite` | Do not manage them unless asked | verified |
| P-057 | CloudFront cache settings | `forwarded_values` is deprecated in favour of `cache_policy_id` and `origin_request_policy_id` | Emit cache policy IDs only | verified |
| P-058 | Route 53 change rate | A second change to a zone while one is processing returns `PriorRequestNotComplete`; API calls are throttled | Batch records; retry with backoff | verified |
| P-059 | ALB deletion protection | With `enable_deletion_protection` the API refuses delete, so `terraform destroy` fails until it is turned off | Turn it off in a separate apply before destroy | verified |
| P-060 | IAM role inline and managed arguments | `inline_policy` and `managed_policy_arns` on `aws_iam_role` are deprecated, take exclusive control and conflict with the separate resources; an empty block removes policies made elsewhere | Emit only `aws_iam_role_policy` and `aws_iam_role_policy_attachment` | verified |
| P-061 | IAM attachment resources | `aws_iam_role_policy_attachment` and `aws_iam_policy_attachment` for the same role show a permanent difference | Never emit `aws_iam_policy_attachment` | verified |
| P-062 | IAM role name and path | `name` forces a new role; with `aws_iam_policy_attachment`, changing name or path needs `force_detach_policies = true` or fails with `DeleteConflict` | Treat the role name as immutable; leave `force_detach_policies` false unless replacing deliberately | verified |
| P-063 | EC2 instance profile | A separate resource; the name must be unique (`EntityAlreadyExists` otherwise); `role` is singular; swapping the role of a running instance can take up to an hour and is eventually consistent | Replace the profile rather than editing the role inside it; reference the profile name | verified |
| P-064 | IAM customer managed policy | `name` and `description` force a new policy; the document updates in place | Warn before renaming | verified |
| P-065 | Policy variables | AWS policy variables such as `${aws:username}` collide with Terraform interpolation; the data source takes `&{...}` for them | Escape in `aws_iam_policy_document`; build with the data source rather than string templates | verified |
| P-066 | IAM destroy order | A role cannot be deleted while policies are attached through `aws_iam_policy_attachment`; Lambda network interfaces need the execution role until they are gone; an ECS service stuck in `DRAINING` needs the role policy to outlive it | Destroy consumers first, role policies last; `depends_on` the role policy from the ECS service (P-028) | verified |
| P-067 | Trust policy source | The `assume_role_policy` argument cannot be an `aws_iam_policy` resource | Use `jsonencode` or the data source | verified |
| P-068 | IAM propagation | A role or profile just created may not be usable by the next resource immediately (eventual consistency) | Reference the role ARN so the order is right; allow a retry on creation errors | verified for instance profiles (S7 of iam-role); general for roles, `unverified` |
| P-069 | Merged policy documents | In `aws_iam_policy_document`, statements without a non-blank `sid` cannot be overridden; `source_policy_documents` need unique sids; `override_policy_documents` replace matching sids; `"Principal": "*"` and `{"AWS": "*"}` differ | Give every generated statement a `sid` derived from the relation; use `type = "*"` or `"AWS"` deliberately | verified |
| P-070 | S3 endpoint route table style | `aws_vpc_endpoint.route_table_ids` and `aws_vpc_endpoint_route_table_association` managing the same association conflict and overwrite each other | Emit one association resource per route table; never set `route_table_ids` on the endpoint | verified |
| P-071 | Endpoint route is not an `aws_route` | The route to the S3 prefix list is added by AWS when a table is associated; it can be viewed but not modified or deleted by hand | Never emit `aws_route` for an endpoint; never import the route. How the route shows in `aws_route_table` state is unverified | verified |
| P-072 | Gateway endpoint policy principal | The `Principal` must be `*`; `"AWS": "<account id>"` grants the account root user only | Use `aws:PrincipalArn` or `aws:PrincipalAccount` conditions | verified |
| P-073 | Endpoint arguments that replace it | The provider page names only `private_dns_enabled` as forcing replacement for a non-Interface endpoint; whether `service_name`, `vpc_id` and `vpc_endpoint_type` force replacement is not stated | Never set `private_dns_enabled` on a gateway endpoint; treat the other three as replacing | verified for `private_dns_enabled`, unverified for the rest |
| P-074 | Switching routes breaks connections | Creating or changing an endpoint changes routes and drops open TCP connections to S3; they do not resume | Warn that an apply may interrupt running transfers | verified |
